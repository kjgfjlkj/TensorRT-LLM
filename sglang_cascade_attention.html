核心问题：当 topk > 1 时，同一 batch 中每个请求有多条候选 token 序列，它们共享相同的 KV Cache 前缀，但每条序列又有自己独立的 draft tokens，且各 draft token 之间的可见性由树形结构的 custom_mask 决定。

为何需要 Cascade Attention？

在 Target Verify 阶段，每个 draft token 需要注意两部分 KV：

为何拆分成两阶段？

1

前缀注意力可批量高效处理

所有 draft token 都可以完整地看到公共前缀，无需特殊 mask，用标准 flash_attn_with_kvcache 即可高效处理。

2

Draft token 注意力需要 custom_mask

每个 draft query 对其他 draft token 的可见性由树结构决定（custom_mask），FA3 接口不直接支持 custom mask，需要通过重排 page_table + cache_seqlens 来等效实现。

3

数学等价合并

两次 attention 的输出可以用 merge_state_v2 通过 log-sum-exp 技巧精确合并，等价于在所有 token 上做单次 attention。

注意：对 Sliding Window Attention (SWA) 层不使用 Cascade Attention，因为第一阶段的 cascade 中每个 query 的 window_size 不同，而 FA3 接口不支持传入 window_size 列表。SWA 层有独立的 swa_spec_metadata 处理路径。

Custom Mask 处理：构建 expand 页表

这是整个设计中最精妙的部分：如何在不修改 FA3 接口的情况下，用 custom_mask 控制哪些 draft token 对哪些 query 可见。

核心思路：用 page_table 重排替代 custom_mask

FA3 的 flash_attn_with_kvcache 通过 cache_seqlens_int32[i] 决定第 i 个 batch 条目读取 page_table[i] 的前多少个 page。利用这一机制：将可见的 draft token page 放前面，不可见的放后面，cache_seqlens_int32 设为可见数量，FA3 自然只会读可见部分。

为什么 causal=False？在 Target Verify 场景，draft token（query）想要看到的是整个前缀 KV，前缀 KV 全部在时间上早于 draft token，因此不需要 causal mask。若用 causal=True，排序在后面的 draft query 会因为 causal 规则无法看到更早位置的前缀 KV，导致结果错误。

关键设计：k_cache 的 view 变换
Stage 2 中 k_cache.view(-1, 1, ...) 将 page_size 维度折叠掉，把每个 KV slot 当作一个独立的 page（page_size=1）。这样 page_table 中存的直接是 slot 的绝对索引（不需要除以 page_size），可以精确地逐 token 控制 KV 访问，从而实现 custom mask 的效果。

merge_state_v2：合并两阶段注意力输出

FlashAttention 的 online softmax 算法维护两个量：输出 o 和 log-sum-exp lse。

数学原理

设 Stage 1 的结果为 (o₁, lse₁)，Stage 2 的结果为 (o₂, lse₂)，则合并后：

# lse = log(sum_of_exp_scores)
# o = (sum_of_exp_scores * v) / sum_of_exp_scores

lse_merged = log(exp(lse₁) + exp(lse₂))
           = lse₁ + log(1 + exp(lse₂ - lse₁))  # 数值稳定版本

w₁ = exp(lse₁) / (exp(lse₁) + exp(lse₂))
w₂ = exp(lse₂) / (exp(lse₁) + exp(lse₂))

o_merged = w₁ * o₁ + w₂ * o₂
# forward_extend line 927-932
# softmax_lse shape: (H, bsz*D) → 转置为 (bsz*D, H) 以匹配 merge_state_v2 的期望
o, _ = merge_state_v2_wrapper(
    o,                                   # Stage 1 output (bsz*D, H, v_head_dim)
    softmax_lse.T.contiguous(),          # Stage 1 lse (bsz*D, H)
    o_expand,                            # Stage 2 output (bsz*D, H, v_head_dim)
    softmax_lse_expand.T.contiguous(),   # Stage 2 lse (bsz*D, H)
)
# merge_state_v2_wrapper 有 @torch._dynamo.disable() 装饰器

SWA 层特殊处理：_init_sliding_window_attn_spec_metadata

对于 Sliding Window Attention 层，cascade attention 不适用。代码通过 _init_sliding_window_attn_spec_metadata 将前缀和 draft tokens 合并成单一序列。

不用 cascade 的原因（注释 line 808-810）：
第一阶段 cascade attention 中，每个 q 的 window_size 是不同的（取决于位置），但 FA3 接口不支持传入 window_size 列表。此外，SWA 层的 seq_len ≤ window_size，重复计算公共前缀的开销也很小，可以直接展开处理。

page_size > 1 时的额外处理（Draft Decode）

当 page_size > 1 时，KV cache 按 page 分配，需要额外调整 cascade attention 的两个 metadata，以确保 Stage 1 不跨页混读，Stage 2 处理页内的尾部 token。

问题：KV cache 的最后一个 page 可能只有部分被填满（last_page_lens = seq_lens % page_size）。Stage 1 使用 strided page table，必须对齐到 page 边界；Stage 2 需要处理最后 page 中剩余的 last_page_len 个 token。

设计亮点总结

无侵入式 custom mask

通过重排 page_table + 设置 cache_seqlens，在不修改 FA3 接口的前提下实现了任意 custom mask，兼容性好。

数学精确的分块合并

使用 online softmax 的 merge_state_v2，两阶段结果的合并在数学上等价于单次全局 attention，不损失精度。

SWA/普通层分治

SWA 层因 window_size 限制走独立路径（合并序列单次 attention），普通层走 cascade 路径，充分利用各场景优势。

page_size 对齐

page_size>1 时通过拆分最后不完整页到 Stage 2，保证 Stage 1 严格对齐 page 边界，避免 KV cache 读取越界。

CUDA Graph 兼容

metadata 在 init_replay_cuda_graph 中用 copy_ 更新，避免动态内存分配，保证 CUDA Graph 的 replay 正确性。

torch.compile 防护

merge_state_v2 通过 @torch._dynamo.disable() 包装，规避已知的 torch.compile 兼容性问题。
