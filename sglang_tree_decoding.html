1 整体架构与工作流程
投机采样的核心思想

投机采样用一个轻量的 Draft Model（草稿模型）提前生成多个候选 token，再用 Target Model（目标模型）一次性并行验证。 当 topk > 1 时，Draft Model 在每一步会保留 k 个候选，形成树状结构（而非单链），显著提升接受率。

2 Draft 阶段：树结构 Token 生成
select_top_k_tokens() — 每步如何展开树节点

Draft Model 每步运行一次，产生 topk 个候选分支。 第 0 步从 verified_id（上次验证接受的最后 token）出发； 第 i 步对上一步的每个候选并行展开，再从所有组合中保留得分最高的 topk 个。 

# Step 0: 从 root 展开 topk 个候选
# topk_p[b, topk], topk_index[b, topk]
tree_info_0 = (
  topk_p.unsqueeze(1),  # [b, 1, topk]
  topk_index,           # [b, topk]
  torch.arange(-1, topk) # parents: 都是 root(-1)
)

# Step i>0: 从上一步 topk 个节点各展开 topk
# expand_scores[b, topk²] = 父score × 子prob
expand_scores = scores[:, :, 1] * topk_p  # [b,k,k]
topk_cs_p, topk_cs_index = fast_topk(
    expand_scores.reshape(bs, -1), topk)  # [b,topk]

# 记录每个被选中节点的父节点位置
parents = topk_cs_index + offset  # 指向上一步的哪个节点
parent_list 与 top_scores_index 数据结构

parent_list[bs, topk*(depth-1)+1] — 记录所有候选节点对应的原始展开位置（用于向上追溯父链）。

top_scores_index[bs, draft_token_num-1] — 每个最终被选中节点在展开矩阵中的绝对索引。 

# topk=2, depth=3 示例
# parent_list: [bs, topk*(depth-1)+1] = [bs, 5]
parent_list = [
  #  slot:  0      1      2      3      4
  [ -1,   0,     2,     0,     2   ]
  # root  t₀     t₁     t₀₀    t₁₀
  # (slot 1,2 = depth1; slot 3,4 = depth2)
]

# top_scores_index: [bs, draft_token_num-1]
# 共 5-1=4 个 draft token (不含 root)

3 build_tree_kernel_efficient — 构建 Tree Mask 与导航结构

核心职责： 给定 parent_list 和 top_scores_index，CUDA kernel 在 GPU 上为每个 batch 中的每个 draft token（一个 thread） 计算其在注意力矩阵中的可见性（tree_mask）、序列位置（positions），以及用于树遍历的导航数组。

QLEN_ONLY 模式下的 Tree Mask 可视化（topk=2, depth=3）

树内部的注意力掩码是一个 [draft_tokens × draft_tokens] 的矩阵。 每个 token 只能看到自己在树路径上的祖先 token，无法看到兄弟或无关分支。

关键规则：树中每个 token 只能 attend 到它在树上的祖先路径， 这保证了 Target Model 的每个 draft token 都能独立地被并行计算 logits， 同时保持正确的因果顺序（不会看到"未来"的 token）。 

# CUDA kernel 构建 mask 的核心逻辑
# 每个 thread 处理一个 draft token tid

if tid == 0:  # root token
    mask[bid, 0, 0] = True   # 只看自己
else:
    # 沿父链向上追溯，标记所有祖先为可见
    cur = tid - 1
    while True:
        mask[bid, tid, cur+1] = True  # 标记可见
        # parent = top_scores_index[cur] // topk
        parent = selected_index[cur] // topk
        if parent == 0: break  # 到达 root
        cur = find_parent_pos(parent)
    mask[bid, tid, 0] = True  # root 也可见

位置编码（positions）： 每个 draft token 的位置 = 前缀长度 seq_len + 其在树中的深度。 Root 的 position = seq_len + 0，depth=2 的节点 position = seq_len + 2。

4 Target Model 验证：带 Tree Mask 的并行 Attention
FULL_MASK 模式下的完整 Attention 矩阵

Target Model 使用 定制的 Attention Mask 一次性处理所有 draft tokens。 每个 draft token 既要 attend 到 KV Cache 中存储的前缀（prefix），又要 attend 到树上的祖先 tokens。

5 验证阶段：DFS 树遍历找最长接受链
VerifyTreeGreedy — CUDA Kernel 逻辑
// grid=(bs,) block=(1,) — 每个 seq 串行遍历
// 但不同 seq 并行，batch 级别有并行
__global__ void VerifyTreeGreedy(...) {
  int bid = blockIdx.x;

  // Step 1: root 直接接受
  int last_accepted = retrive_index[bid, 0];
  accept_index[bid, 0] = last_accepted;
  int num_accepted = 0;
  int cur_index = 0;  // root

  // Step 2: 逐层向下遍历
  for (int j = 1; j < num_spec_steps; j++) {
    // 获取第一个子节点
    cur_index = retrive_next_token[bid, cur_index];

    // 遍历当前层的所有候选（兄弟链）
    while (cur_index != -1) {
      int draft_tok = candidates[bid, cur_index];
      int target_tok = target_predict[last_accepted];

      if (draft_tok == target_tok) {
        // ✓ 接受：沿此路径继续
        predicts[last_accepted] = target_tok;
        accept_index[bid, ++num_accepted] =
            retrive_index[bid, cur_index];
        last_accepted = retrive_index[bid, cur_index];
        break;
      } else {
        // ✗ 拒绝：尝试下一兄弟
        cur_index = retrive_next_sibling[bid, cur_index];
      }
    }
    if (cur_index == -1) break;  // 全部拒绝
  }
  accept_token_num[bid] = num_accepted;
}

6 topk > 1 时的 KV Cache 管理

难点：当 topk > 1 时，每个 draft token 对应的 KV 需要存储在独立位置（不同分支共享前缀但各有自己的扩展）。 验证后需要将接受路径的 KV 拷贝到连续位置，并释放不接受的分支。

核心权衡： topk > 1 通过保留多条候选路径显著提升接受率（每次投机解码轮次平均接受更多 token）， 代价是 KV Cache 增加约 topk 倍，以及 Attention Mask 计算更复杂。 在 GPU 内存充足的情况下，topk=2 通常是最优平衡点。
