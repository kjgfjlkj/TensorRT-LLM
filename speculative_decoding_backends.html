§ 4 · TRT 后端内部模式详解（C++ 位标志）

None

标准自回归解码，无投机。每次迭代仅生成 1 个 token。

TRT kNone = bit 0

DraftTokensExternal

草稿 token 由外部系统提供（用户编排双 Executor 模式）。目标模型仅负责验证。草稿长度可变。

TRT kDraftTokensExternal = bit 1 variableDraftLength

Medusa

模型内置多个额外语言模型头，每个头预测不同位置的 token。头的输出形成草稿树（树形注意力掩码）。有独立的草稿 logits。

TRT kMedusa = bit 2 hasDraftLogits requiresAttentionMask needsKVCacheRewind

LookaheadDecoding

Jacobi 迭代式解码，无需额外模型。通过并行猜测多个 token 形成候选序列，同一模型验证。位置 ID 动态更新。

TRT kLookaheadDecoding = bit 3 updatesPositionIds variableDraftLength needsDecoderPrologue

ExplicitDraftTokens

草稿 token 显式传入验证阶段（ReDrafter 风格）。需要 Decoder Prologue 预处理步骤，草稿长度可变。

TRT kExplicitDraftTokens = bit 4 updatesPositionIds needsDecoderPrologue variableDraftLength

Eagle (v1 / v2)

EAGLE 算法：草稿模型基于目标模型的 feature（隐状态）自回归预测。Eagle-2 支持动态树。需要注意力掩码和 KV 回退。

TRT + Torch kEagle = bit 5 requiresAttentionMask needsDecoderPrologue variableDraftLength

§ 5 · 各自独有能力

⚙️ TensorRT 后端 · 独有优势
🧠
Medusa 多头树形草稿
TRT 后端独家支持 Medusa 草稿头，有独立草稿 logits；可探索指数级路径同时验证，PyTorch 后端不支持。
👁️
Lookahead Decoding
无需任何额外模型的投机解码方式，通过 Jacobi 迭代生成草稿，TRT 后端原生支持，PyTorch 后端不支持。
📋
ExplicitDraftTokens (ReDrafter)
ReDrafter 风格的草稿机制，通过 Decoder Prologue 流程管理草稿 token，TRT 特有。
🏗️
C++ 层深度集成
投机解码逻辑嵌入 BatchManager/KV Cache C++ 层，调度与验证高度融合，性能更接近底层。
⛓️
Triton Backend 集成
可通过 Triton Inference Server BLS 进行 Draft-Target 编排，支持 gRPC 客户端端到端投机解码。
🔥 PyTorch 后端 · 独有优势
🦅
Eagle3 (最新 EAGLE 算法)
捕获目标模型多层隐状态作为草稿输入，OneModel 单引擎模式大幅简化部署，TRT 后端仅支持 Eagle v1/v2。
🔀
MTP (Multi-Token Prediction)
DeepSeek 专用：多个 MTP 预测层内嵌模型，支持放宽接受（Thinking 阶段），TRT 后端不支持。
🌲
SA (Suffix Automaton)
GPU 原生后缀自动机，支持最长子串匹配，可与 MTP 混合使用（use_sa_spec），CUDA Graph 兼容。
⚡
PARD (并行自回归草稿)
目标无关的草稿方法，单次前向即可并行生成 K 个草稿 token，无需目标模型隐状态。
🚪
SpeculationGate 自适应禁用
滑动窗口监控接受率，低于阈值时永久禁用投机，避免高 batch 下的性能退化，TRT 后端无此机制。
🛠️
UserProvided + Auto 可扩展性
实现 Drafter 接口即可接入任意自定义草稿逻辑；Auto 模式根据模型架构启发式推荐算法。
