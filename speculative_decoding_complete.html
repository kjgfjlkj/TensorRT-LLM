§1 投机解码原理总览

每次迭代输出 1 ~ max_draft_len + 1 个 token（vs 标准解码每次仅 1 个）
Draft 机制
快速生成
max_draft_len 个候选 token
→
Target Model
单次前向传播
并行验证所有草稿
→
Token 验证
逐位比较
截断在首个不匹配处
→
输出 Tokens
0..N 个草稿
+ 1 个目标 token

两种主要引擎架构

🔁 双引擎 (2-Model)
草稿模型与目标模型使用独立引擎，各有独立 KV Cache
EAGLE v1/v2 (TRT) Eagle3 2-model MTP-Eagle Draft/Target 外部编排
🔗 单引擎 (1-Model / OneModel)
草稿模块与目标模型共享同一引擎，无需额外模型加载
Medusa (TRT) Lookahead (TRT) MTP / MTP-Eagle-1M Eagle3 OneModel SA / PARD / NGram

KV Cache 三种处理策略

⏪ KV Rewind（回退）
被拒绝的草稿 token 对应的 KV block 需要撤回。
适用：MTP、Eagle3-1M、NGram、SA、PARD、DraftTarget
🔁 KV Recompute（重算）
草稿模型第一次前向需为已接受 token 重算 KV。
适用：Eagle3 双引擎、MTP-Eagle 双引擎
🗂️ 独立草稿 KV Cache
目标与草稿使用不同 block 布局，通过 context manager 切换。
适用：部分单引擎模式（_allow_separate_draft_kv_cache）

1️⃣

3️⃣

1️⃣

§7 TRT 后端内部模式（C++ 位标志）

源文件: cpp/include/tensorrt_llm/runtime/speculativeDecodingMode.h · 每个模式为独立位，存储在 uint8_t 中
bit 0 · kNone
None
标准自回归解码，无投机，每次仅生成 1 个 token
TRTbit 1 · kDraftTokensExternal
DraftTokensExternal
草稿 token 由外部系统提供，目标模型仅负责验证。草稿长度可变 (variableDraftLength)
TRT 专有bit 2 · kMedusa
Medusa
多个额外 LM 头预测未来 token，树形注意力掩码。有独立草稿 logits (hasDraftLogits)，需 KV Rewind
hasDraftLogitsrequiresAttentionMaskneedsKVCacheRewind
TRT 专有bit 3 · kLookaheadDecoding

Jacobi 迭代式解码，无需额外模型。位置 ID 动态更新，草稿长度可变
updatesPositionIdsvariableDraftLengthneedsDecoderPrologue
TRT 专有bit 4 · kExplicitDraftTokens
ExplicitDraftTokens
ReDrafter 风格，草稿 token 显式传入验证，需 Decoder Prologue 预处理步骤
updatesPositionIdsneedsDecoderProloguevariableDraftLength

Eagle (v1/v2)
草稿模型使用目标隐状态自回归预测候选 token。Eagle-2 支持动态树 (EAGLE-2 算法)

§8 Eagle 系列在两后端的映射关系

用户配置类
EagleDecodingConfig

decoding_type="Eagle3"
TRT 后端
PyTorch 后端 · 自动升级
PyTorch 后端专用
后端内部模式
C++ kEagle (Eagle v1/v2)动态树 Eagle-2 · 静态树 · variableDraftLength
Torch EAGLE3 / EAGLE3_ONE_MODELEagleDecodingConfig 在 PyTorch 下自动升级 → Eagle3
Torch EAGLE3_ONE_MODEL (默认) / EAGLE3隐状态捕获 · OneModel 单引擎 · Overlap Scheduler
注意： 在 PyTorch 后端传入 EagleDecodingConfig(decoding_type="Eagle") 会触发警告并自动升级为 Eagle3。 在 TRT 后端使用 Eagle3DecodingConfig 会报错——TRT 仅支持 Eagle v1/v2 (kEagle 位)。 两者共用同一配置类名但内部路径完全不同。
