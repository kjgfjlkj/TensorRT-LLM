01 投机采样总览

投机采样的核心思路：用小的 草稿模型（Draft） 快速生成多个候选 token，再用大的目标模型（Target）一次性并行验证，从而提升吞吐量。当 topk > 1 时，每步生成多个候选，形成一棵 token 树（Token Tree），进一步提升接受率。

为什么用树形解码？

线性投机采样（topk=1）每步只生成一个候选，若被拒绝则浪费。树形解码每步生成多个候选，增加验证命中率。

topk=4, depth=3 时最多可验证 21 个 token，只需 1 次目标模型前向！

EAGLE 的特点

EAGLE 草稿模型利用目标模型的 hidden states 作为额外输入，大幅提升 draft 精度。EAGLE3 进一步改进了特征聚合方式。

Shared LM Head：草稿模型与目标模型共享词表头，节省显存并保证概率空间一致。

08 Tree Attention Mask

目标模型并行验证时，每个 draft token 只能 attend 到其祖先节点，不能跨分支。这通过自定义的 Tree Mask 实现，由 CUDA 核在树构建时同步填充。

Flash Attention 接受的掩码格式由 tree_mask_mode 控制。QLEN_ONLY_BITPACKING 用位压缩表示，可显著减少显存占用，适合 topk 较大的场景。

09 关键参数与性能配置

参数说明推荐值（Llama）影响
--speculative-algorithm投机采样算法EAGLE3精度 / 速度权衡
--speculative-num-steps树深度（自回归步数）3 ~ 5越深候选越多，draft 开销增大
--speculative-eagle-topk分支因子（每步候选数）4越大树越宽，接受率↑，显存↑
--speculative-num-draft-tokens最大验证 token 数16限制实际树节点，避免显存爆炸
--speculative-accept-threshold-single单 token 接受阈值1.0（严格）降低可提高接受率但降低输出质量
--speculative-accept-threshold-acc累积接受阈值1.0（严格）同上

树节点数计算

nodes = (topk**depth - 1) // (topk - 1) topk=4, depth=3 → 21 节点 topk=2, depth=5 → 31 节点 topk=1, depth=5 → 5 节点（线性） actual = min(nodes, num_draft_tokens)

吞吐量提升

理论加速比 ≈ 平均接受长度 / (1 + draft_cost_ratio)。EAGLE3 + topk=4 在 Llama-3 上实测约 2~4x 吞吐提升。

每次目标模型前向可验证 16 个候选，平均接受 3~6 个，等效于普通解码的 3~6 步！
